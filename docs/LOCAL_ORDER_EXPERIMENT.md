# 本地六组任务顺序实验：开发预览

本分支增加顺序实验所需的代码，版本为 `0.3.0.dev0`。它尚未完成真实
OFT 推理验收，不能据此得出模型是否遵循指令的结论。原有稳定版保留在
`main` 分支。

本分支的开发包：[源码 ZIP](../downloads/openvla-source.zip)、
[Python 安装包](../downloads/openvla_trajectory_tools-0.3.0.dev0-py3-none-any.whl)。

## 实验范围

沿用 `moojink/openvla-7b-oft-finetuned-libero-10`，使用 `libero_10`、
`load_in_4bit=True`、`num_trials_per_task=1`。六组任务分别是奶酪与黄油、
汤罐与奶酪、双杯左右盘、白杯与布丁、左右摩卡壶、开炉与放壶。
每组的 AB、BA 两种指令各运行 20 个官方初态，共 240 个模型回合。
同一组两种指令使用相同的初态内容，而不仅比较初态编号。

任务、英文指令和运行时目标谓词保存在
[`plans/libero10-order-six.json`](../plans/libero10-order-six.json)。以下命令
只检查计划，不加载模型，也不产生实验结果：

```powershell
python scripts/run_order_experiment.py describe
```

## 程序怎样执行和记录

运行入口为 `scripts/run_order_experiment.py run`。执行端提供已安装 OFT 的
`--oft-root`、原模型已下载的 `--checkpoint-dir`、本地数据 `--output`，以及
可选的 `--libero-config`。这些参数由执行实验的代理根据实际安装位置填写，
本文件没有需要用户替换的示例路径。

程序先解析全部任务与初态，固定共享指纹，再逐个条件调用官方评估器。
每个条件使用一个独立进程，模型在该条件内只加载一次。先加
`--max-new-episodes 1` 进行一个真实模型回合的试运行；检查权重、视频、
实际模型指令和记录后，去掉该参数继续完成剩余回合。

记录器会真正替换传给 `run_episode` 的指令，并核验每一次 `get_action`
收到的文本。官方 `obs`/`task_label` 参数名与兼容接口均受支持。
`queries.json` 保存实际指令、SHA256、动作块编号及查询完成/错误状态；
模型收到错误指令时实验中止并保留错误记录。

每个回合保留逐步原始数组、目标谓词、`manifest.json`、`execution.json`、
查询记录、MP4 和视频帧映射。完整且证据匹配的失败回合也计入一次实验，
不会为了获得成功而重跑。中断、损坏或身份不匹配的记录保留为历史尝试。
续跑必须同时匹配状态内容、实际指令、配置和模型/源码指纹。

OFT 会在加载本地模型时产生配置备份并同步 Python 文件。模型指纹排除
这些生成的备份，规范化由 OFT 覆盖的 `auto_map`，并另外记录 OFT 源码指纹。
其余有效模型输入的变化会产生新的实验身份。模型文件指纹能证明字节内容，
不能单独证明下载来源；执行端还必须保留标准模型的下载版本记录。

本机 PyTorch 2.9 读取官方 NumPy 初态时使用限定的安全类型列表，不关闭全局
`weights_only` 检查。Numba 缓存写到实验输出目录。每个新回合开始前要求至少
剩余 2 GiB 磁盘空间；这只是防止记录写满磁盘的保护，不代表磁盘足以容纳
全部 240 回合。真实试采后仍需按实际回合大小估计剩余容量。

## 表格怎样解释

`results/episodes.csv` 为每个已核验完成的计划行选择一个回合；
`results/summary.csv` 按任务和条件汇总。
`attempts/` 另保留所有实际记录尝试的分类，包括中断和错误。
没有运行的计划行不会被填成失败或伪造为实验结果。

- **子目标完成顺序**：根据连续观测到的假→真谓词事件得到 AB、BA、同一步
  或未知；缺少早期证据、初态已满足、未观察到完成等情况均保留原因。
- **抓取顺序**：只使用独立核验的抓取证据或人工视频标注，不能从放置目标的
  完成顺序推断。没有抓取标注时该列为未知；第六组开炉不是抓取事件。
- **官方任务成功**、**指令顺序符合**分别统计。未知结果与无法判定的顺序
  有各自数量和分母，不混入失败率；中断轨迹可以保留已观测事件顺序，但其
  完整回合成功/符合判断为空。

表格还记录模型与量化参数、实际指令和哈希、初态指纹、事件所在记录步、
策略动作步、可用的视频帧位置与证据路径。MP4 可用性检查不等于独立解码
验收；正式试采仍须播放并核对视频与原始记录。

## 2026-11-23 本机核验边界

本机 RTX 5070 Ti 的 CUDA 运算和六个场景的无模型仿真预检此前已通过。
本轮读取了官方 OFT 评估器/动作接口源码，并用本机真实 LIBERO 初态读取器
解析出 12 个条件、240 条配对计划，内容指纹匹配。CPU 测试已覆盖指令传递、
分类、续跑、模型备份与初态变化。全套测试为 312 passed、2 skipped；两项
跳过分别是基础测试环境缺少可选 MP4 编码器和 PyTorch。NumPy 初态兼容处理
另在实际已安装的 PyTorch 2.9 环境中验证通过。开发 wheel 已在隔离目录安装并
检查版本、任务配置与 CLI；源码 ZIP 已逐文件核对。独立代码复审通过。
